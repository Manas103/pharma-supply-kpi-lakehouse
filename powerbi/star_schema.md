# Power BI star schema

One star schema, built from the gold layer (`kpilake/gold.py`). Exported
here as small CSVs (`dim_plant.csv`, `dim_product.csv`,
`dim_business_unit.csv`, `fact_gold_sample.csv`) for a reader to see the
shape without opening Power BI Desktop, which is not installed on this
build machine (README, "Honest framing"). The full gold Parquet tables
(1.2M-row `fact_order_line_gold`, 30,000-row `fact_batch_gold`) are what a
real Power BI Desktop import would point at with Power BI's Parquet
connector; they are regenerated by `python scripts/run_pipeline.py` and
are not tracked in this repository (`.gitignore`).

## Fact tables

- `fact_order_line_gold` (grain: one row per order line, partitioned by `month_index`)
  Columns: `order_id`, `plant_id`, `product_id`, `customer_id`, `business_unit`,
  `qty_ordered`, `qty_shipped`, `promised_date_day`, `delivery_date_day`,
  `shipped`, `on_time_delivery`, `in_full_delivery`, `otif`, `backorder`, `month_index`.
- `fact_batch_gold` (grain: one row per batch, partitioned by `month_index`)
  Columns: `batch_id`, `plant_id`, `product_id`, `batch_start_day`,
  `batch_mfg_end_day`, `batch_release_day`, `batch_mfg_cycle_days`,
  `batch_release_cycle_days`, `qc_result`, `deviation_count`, `deviation_flag`,
  `right_first_time`, `month_index`.

## Dimensions

- `dim_plant` (`plant_id`, `name`, `region`) — 3 rows.
- `dim_product` (`product_id`, `family`, `base_unit`, `batch_yield_units`) — 6 rows.
- `dim_customer` (`customer_id`, `region`, `business_unit`) — 260 rows.
- `dim_business_unit` (`business_unit`) — 3 rows, the row-level-security dimension (`rls.md`).
- `dim_date` (`day_index`, `month_index`) — one row per simulated day across the 24-month horizon.

## Relationships

`fact_order_line_gold[plant_id] -> dim_plant[plant_id]` (many-to-one)
`fact_order_line_gold[product_id] -> dim_product[product_id]` (many-to-one)
`fact_order_line_gold[customer_id] -> dim_customer[customer_id]` (many-to-one)
`fact_order_line_gold[business_unit] -> dim_business_unit[business_unit]` (many-to-one)
`fact_batch_gold[plant_id] -> dim_plant[plant_id]` (many-to-one)
`fact_batch_gold[product_id] -> dim_product[product_id]` (many-to-one)

`fact_order_line_gold` and `fact_batch_gold` do not relate to each other
directly in the star (both relate through `dim_plant` / `dim_product`);
the raw link between an order line and the batch that fulfils it lives in
silver (`fact_order_line_silver.batch_id`) and is used to build the
correlated fulfilment outcome, not exposed as a star-schema relationship,
since Power BI report pages read plant/product/business-unit cuts, not a
line-to-batch drill path.
